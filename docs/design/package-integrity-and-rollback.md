# Package integrity and rollback

`INTEGRITY.sha256` is the release-tree manifest for production Python files
under `src/`. It is generated rather than hand-maintained:

```powershell
py -3.12 tools/compute_integrity_hash.py write
py -3.12 tools/compute_integrity_hash.py check
```

Run `check` before publishing a release candidate. A non-zero result means
the source tree and manifest differ, so the candidate must not be described
as verified.

## What the manifest covers

The manifest covers importable package source, not generated bytecode, build
directories, test fixtures, or documentation. It complements rather than
replaces a wheel build: public CI builds a wheel, installs it outside the
checkout, and imports the installed package.

## Release identity

For each release, retain these together:

1. the versioned Git tag;
2. the corresponding `INTEGRITY.sha256` manifest; and
3. the wheel produced from that tagged revision.

Git hosting and a checksum prove different things. The tag identifies the
revision, while the manifest lets a reviewer compare the production source
tree with that revision. No code-signing claim is made unless a release is
actually signed and the signature-verification instructions are published.

## Rollback

Rollback means selecting the prior known-good release tag, rebuilding or
retrieving its retained wheel, verifying the manifest, then running the
quality gate before restarting the MCP server. Do not silently point a live
registration at an arbitrary working tree: record the target version and
restart intentionally so the running process matches the chosen release.

The project is not a package index registry. Until an index release process
exists, distribution and rollback are repository-release operations.
